# AI Kubernetes Ops Assistant

A read-only Kubernetes operations assistant that collects cluster health signals, detects common workload failures, and produces structured incident reports. An optional LLM layer can turn the deterministic findings into an operator-friendly explanation.

## Why this is different from a chatbot

The tool does not ask an LLM to guess what is wrong from an unstructured prompt. Kubernetes data is collected first, deterministic rules identify evidence, and AI is limited to explaining those findings and suggesting reviewable next steps.

## Safety model

- Read-only Kubernetes RBAC
- No create/update/delete permissions
- No shell execution generated by an LLM
- Secrets are never intentionally collected
- Deterministic evidence remains visible alongside AI output

## Detects

- CrashLoopBackOff
- ImagePullBackOff / ErrImagePull
- OOMKilled containers
- Pending pods
- failed scheduling and warning events
- unhealthy container readiness

## Run locally

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m ops_assistant.cli --fixture tests/fixtures/problem_snapshot.json
```

For a real cluster:

```bash
python -m ops_assistant.cli --namespace default
```

The Kubernetes client uses the current kubeconfig context, or in-cluster configuration when deployed in Kubernetes.

## Architecture

Kubernetes API (read-only) -> Collector -> Rule Engine -> Incident Report -> optional LLM Explainer
